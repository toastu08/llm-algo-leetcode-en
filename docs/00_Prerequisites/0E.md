# Group 0E: Runtime Diagnostics and Experiment Foundations

## Group Overview

First determine whether a run is valid, then explain elapsed time and capacity. 19 locates errors and non-finite values; 17 actually collects CPU timing and stage events; 18 estimates object capacity and uses a constructed allocator snapshot to practice reconciliation; 20 practices comparison and judgment under fixed conditions.

![0E validity checks, time and capacity branches, and experiment comparison](../public/00_Prerequisites/0e_debugging_performance_map.svg)

## Learning Entries

| Page | When to enter | What you get at runtime |
|:---|:---|:---|
| [19 Debugging and Anomaly Localization](./19_Debugging_and_Anomaly_Localization.md) | Errors, non-finite values, or abnormal outputs or gradients | Exception category, first failure point, and minimal reproduction |
| [17 Profiling Basics](./17_PyTorch_Profiling_Basics.md) | The run is valid, but the elapsed time is abnormal | Actual CPU forward timing and execution trace, plus separately collected training-stage events |

## Learning Path

### Recommended Order

For complete reading, follow 19 → 17 → 18 → 20; when troubleshooting by problem, after confirming the run is valid, choose the time or capacity branch and then go to 20 to compare results. The actual timing in 17, the theoretical estimates and constructed snapshots in 18, and the example records in 20 each retain their own source and must not be treated as measurement results from the same GPU experiment.

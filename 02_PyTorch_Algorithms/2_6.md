# Group 2.6: Inference Execution and Generation Acceleration

This group moves from a single Attention execution to single-request generation, and then compares different candidate topologies for speculative generation. The learning focus is to distinguish “how to execute one forward pass”, “how to choose the next Token”, and “how to use drafts to reduce target-model rounds”.

## Learning Path

### Recommended Order

- Execution path: 20 → `INF-EXECUTION-DISPATCH`; first confirm the Attention data flow, then judge whether an optimization candidate actually hits the backend.
- Generation path: 21 → 23; first fix single-step decoding and the exact verification semantics.
- Draft branch: 35 / `INF-EAGLE` / `INF-PARALLEL-DRAFTING` are studied in parallel, and `INF-PROPOSAL` then unifies the candidate budget and net benefit.

### Next Steps

- Multi-request KV state, dynamic batching, and stage scheduling enter [2.7](./2_7.md).
- Real speculative generation is carried by [68](./68_Speculative_Decoding_Benchmark.ipynb); project pages do not redefine this group's mechanisms.

## Environment Notes

- Step1–4 use the CPU by default to establish mechanisms and state invariants.
- Only 20 and the registered real-model paths use the single-GPU mechanism Profile; synthetic logits or random matrices are not used as GPU performance evidence.

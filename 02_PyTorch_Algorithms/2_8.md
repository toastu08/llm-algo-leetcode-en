# Group 2.8: Quantization and Low-Bit Adaptation

This group focuses on quantization and low-bit adaptation, with the goal of connecting “how to represent, how the range is chosen, which path to take, and how to prove it is worth deploying” into one route. Learning first uses 25 to establish W8A16 representation and granularity, then 52 searches the calibration range and clipping quantile, and then moves into QLoRA, QAT, GPTQ/AWQ, SmoothQuant, mixed bit-width, FP8, and KV Cache quantization. Pruning, distillation, and general sparsification are temporarily treated as later extensions and are not mixed into the current core path.

## Group Overview

This group revolves around “how to reduce storage, bandwidth, or compute cost under acceptable error”. 25 establishes the basic representation, and 52 is responsible for data-driven range selection; 26 and QUANT-QAT distinguish low-bit adapter training from quantization-aware training; 40, 53, and QUANT-MIXED-BIT handle weights, activations, and cross-layer bit-width allocation; 41 and 54 handle FP8 runtime and KV Cache state quantization respectively. Inference quantization first goes through 82 to audit artifact, quality, and compatibility, and then enters the deployment comparison of 66/67.

Non-project pages in this group uniformly follow the notebook-first structure of `26`; group pages only handle the reading path and asset navigation.

## Learning Path

### Recommended Order

The main mechanism route is as follows; 25 first establishes the quantization representation, and 52 then answers how the range is selected from data:

```text
25 W8A16 fundamentals
→ 52 Calibration range and clipping
  ├─ 26 QLoRA low-bit training
  ├─ QUANT-QAT Quantization-aware training
  ├─ 40 GPTQ / AWQ weight quantization
  ├─ 53 SmoothQuant activation quantization
  ├─ QUANT-MIXED-BIT Mixed bit-width allocation
  ├─ 41 FP8 runtime paths
  └─ 54 KV Cache quantization
```

- When training memory is constrained, enter project 65 from 26; when PTQ quality is insufficient and further training is allowed, choose QUANT-QAT. Neither training path can replace the validation of inference quantized artifact.
- QUANT-MIXED-BIT should be studied after 40/53 have produced comparable sensitivity; it is responsible for cross-layer budget allocation and does not repeat the quantization algorithms of each page.
- For inference compression, choose 40, 53, 41, and 54 according to weights, activations, runtime computation, and cache state respectively; the four branches are not required to be studied in order.
- In the project stage, first use [82](./82_Quantization_Artifact_Evaluation_Project.ipynb) to check the artifact gate, then run the matching floating-point–quantized deployment comparison with [67](./67_Quantized_Inference_and_Deployment.ipynb), and finally use [83](./83_Quantized_Serving_Profile_Benchmark.ipynb) to select a Profile according to the serving objective. [66](./66_Inference_Performance_Comparison.ipynb) can serve as a floating-point historical comparison but is not a required upstream of 67.

# Group 2.7: KV Cache and Serving Systems

This group moves from the representation and physical management of the KV Cache into multi-request Serving. The learning path answers in order: how state is stored, when it is allocated and reclaimed, how it is reused across requests, which requests are admitted in each round, and how Prefill, Decode, and heterogeneous resources work together.

## Learning Path

### Recommended Order

- KV path: request state → `ARCH-MLA` → 22 → 37 → 24 → 34; the KV Cache quantization of 54 enters as a compression branch on demand.
- Serving path: `INF-ITERATION-BUDGET` → 36 → `INF-CONTINUOUS-BATCHING` → 38 → `INF-SERVING-OVERLAP` → 39.
- 36 consumes the capacity state provided by 37 but does not manage the block lifecycle; AFD enters only in MoE Serving and when role pressure is asymmetric.

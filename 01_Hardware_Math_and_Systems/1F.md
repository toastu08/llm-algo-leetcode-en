# Group 1F: Hardware Adaptation and System Constraints

Migrating a model to another device may run into problems such as sufficient capacity but an inability to load, preprocessing that runs but generation that fails, tail latency that rises after sharing, and a cheap device with a higher unit cost. This group follows this migration to check, in order, the missing runtime conditions, the resource requirements of each stage, and the isolation and cost trade-offs after running.

## Group Goal

Read the main path in the order 10 → 34 → 33: first filter the device and software conditions, then check the execution requirements stage by stage, and finally compare the cost over the same holding period. Only when multiple tasks need to share a device do you enter 31 between 34 and 33; a single-task migration does not require learning resource slicing first.

## Main Path and Multi-Tenant Branch

Capacity, precision, and software support are first computed with the given conditions; loading, data handoff, and functional results must be checked on the target device. After the real path can execute, fix the workload to measure quality, time, and resources, and only then can the cost model use these results to compare options. For compilation artifacts and shape conditions, see [1E Compilers and Backends](./1E.md); for transfer-time estimates, see [07 Heterogeneous Scheduling](./07_CPU_GPU_Heterogeneous_Scheduling.ipynb).

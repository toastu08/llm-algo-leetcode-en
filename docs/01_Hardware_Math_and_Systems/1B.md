# Group 1B: Single-Device Execution, Memory and Data Access

This group uses a GPU as an example to explain single-device computation, memory, and memory-access constraints.

## Group Goal

This group establishes the three threads needed for single-device resource judgment: what the GPU execution units are responsible for, which memory levels the data passes through, and how the working set of the current stage is formed. Learners start from the shared hardware model and move into attention state, temporary working sets, low-precision matrices, on-chip reuse, or sparse execution branches, and then hand the compute, bandwidth, and capacity assumptions to performance analysis for verification. Runtime compatibility of CPU, GPU, NPU, and TPU is covered by [1F](./1F.md); it is recommended to complete the order-of-magnitude ledger of [1A](./1A.md) first.

## Group Mechanism Chains

First use 03 to understand execution units and memory levels, then choose a branch by problem. Each branch provides compute volume, storage volume, or execution conditions; the exercise in 13 combines the workload with a given elapsed time to distinguish theoretical resource upper bounds, low-utilization symptoms, and bottlenecks still to be verified. Real runs also need timing, execution traces, or residency data for the same workload.

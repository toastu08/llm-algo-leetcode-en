# Group 2.5: Preference Optimization and Alignment

This group starts from the SFT checkpoint saved in 2.4. Before choosing a method, first fix the preference data, the answer evaluation rules, and the meaning of reward: paired preferences enter DPO, and a single binary feedback enters KTO; for online sampling, PPO, GRPO, or RLOO is then chosen according to whether a Critic, group mean, or leave-one-out baseline is used. Continuous sampling and rolling updates also need to record trajectory identity, policy version, and recovery state; when gradients, effective updates, or multi-model training state are abnormal, return to [2.3](./2_3.md), while feedback, reward, policy-version, and trajectory issues stay in this group.

![Selecting DPO, KTO, PPO, GRPO, or RLOO from the feedback form and online baseline, then entering project and system validation](../docs/public/02_PyTorch_Algorithms/2_5_alignment_learning_path.svg)

## Learning Path

First use [50](./50_Preference_Data_and_Evaluation.ipynb) to fix the data split, the meaning of feedback, and the evaluation rules, then choose the corresponding method branch according to the available signal. The online branch starts from [PT-REWARD-SIGNAL](./PT-REWARD-SIGNAL_Reward_Model_Value_and_Advantage.ipynb), distinguishing reward, return, value, and advantage.

| Available training signal | Online generation | Comparison baseline | Corresponding page | Project validation |
|:---|:---:|:---|:---|:---|
| chosen / rejected for the same prompt | No | Preference margin under the reference | [17 DPO](./17_DPO_Loss_Tutorial.ipynb) | [84 DPO project](./84_DPO_Preference_Project.ipynb) |
| Accept / reject label for a single answer | No | Independent KL sample baseline | [PT-KTO](./PT-KTO_Binary_Feedback_Alignment.ipynb) | No standalone project yet |
| Learned scalar reward, with a trained Critic | Yes | Value / GAE | [PT-REWARD-MODEL](./PT-REWARD-MODEL_Reward_Model_Training_and_Calibration.ipynb) → [16 PPO](./16_RLHF_PPO_Memory.ipynb) | No standalone project yet |
| Rewards for multiple answers to the same prompt | Yes | Group mean with optional standard deviation | [18 GRPO](./18_GRPO_Loss_Tutorial.ipynb) | [85 GRPO project](./85_GRPO_Groupwise_Alignment_Project.ipynb) |
| Rewards for multiple answers to the same prompt | Yes | Leave-one-out mean excluding the current answer | [PT-RLOO](./PT-RLOO_Leave_One_Out_Policy_Optimization.ipynb) | No standalone project yet |

### Online Updates and System Validation

Algorithm pages first determine the training signal and loss; during continuous sampling, they also check trajectory version, environment interaction, role capacity, transport, and recovery conditions.

| Scenario | Follow-up entry | Problem solved |
|:---|:---|:---|
| Online DPO | [17](./17_DPO_Loss_Tutorial.ipynb) or [84](./84_DPO_Preference_Project.ipynb) → [51](./51_Online_DPO.ipynb) | Fix the feedback window and decide to adopt, delay, or roll back |
| PPO / GRPO / RLOO continuous sampling | [PT-ROLLOUT-LIFECYCLE](./PT-ROLLOUT-LIFECYCLE_Rollout_and_Policy_Freshness.ipynb) → [PT-RL-SYSTEM](./PT-RL-SYSTEM_Rollout_Training_and_Reward_System.ipynb) | Fix trajectory identity, policy version, role capacity, transport, and recovery conditions |
| Multi-step tool and environment interaction | [PT-AGENTIC-RL](./PT-AGENTIC-RL_Environment_Trajectory_and_Credit_Assignment.ipynb) | Express environment state, model actions, tool observations, terminal / process rewards, and credit assignment |
